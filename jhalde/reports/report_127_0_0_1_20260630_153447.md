## Findings

### [HIGH] SMB Server Elevation of Privilege — Authentication Forwarding Abuse

- **Service:** 445/tcp — microsoft-ds (SMB)
- **CVE:** CVE-2016-3225 (CVSS **7.8**)
- **Description:** The SMB server component in Microsoft Windows allows local users to gain elevated privileges via a crafted application that forwards an authentication request to an unintended service. This vulnerability arises from improper validation of authentication targets within the SMB stack, enabling privilege escalation from a standard user context to SYSTEM-level access.
- **Evidence:** Port 445 was found open and responding during nmap enumeration. The service banner reported `microsoft-ds`, consistent with Windows SMB Server. No patch level or OS version was returned, making it impossible to rule out unpatched status.
- **Recommendation:** Apply Microsoft Security Bulletin MS16-075 or equivalent cumulative update. Restrict SMB access to authenticated, authorised internal hosts only using firewall rules. Enforce SMB signing to prevent relay-based exploitation. Audit local user permissions to minimise the blast radius of privilege escalation.
- **ATT&CK:** T1210 — *Exploitation of Remote Services* (Lateral Movement)

---

### [HIGH] Samba BADLOCK — DCERPC Protocol Downgrade & Impersonation

- **Service:** 445/tcp — microsoft-ds / Samba (SMB)
- **CVE:** CVE-2016-2118 (CVSS **7.5**)
- **Description:** Known as **"BADLOCK"**, this vulnerability affects the MS-SAMR and MS-LSAD protocol implementations in Samba and mishandles DCERPC connections. A man-in-the-middle attacker can perform protocol-downgrade attacks against SMB sessions, allowing them to intercept and impersonate authenticated users by modifying the client-server data stream. This is particularly dangerous in environments where SMB signing is not enforced.
- **Evidence:** Port 445 is exposed with no confirmed SMB signing enforcement. The service version string was not returned by nmap (`version: ""`), indicating either a hardened banner or an older/unpatched Samba/Windows SMB implementation. BADLOCK is exploitable wherever unenforced SMB signing coincides with network adjacency.
- **Recommendation:** Upgrade Samba to 4.2.11+, 4.3.8+, or 4.4.2+ as appropriate. For Windows environments, apply MS16-047. **Enforce mandatory SMB signing** on all clients and servers (`RequireSecuritySignature = 1`). Segment the SMB service behind a network firewall to limit exposure to the local subnet only.
- **ATT&CK:** T1187 — *Forced Authentication* (Credential Access)

---

### [HIGH] Samba SMB2/SMB3 Client-Signing Bypass — MitM Session Spoofing

- **Service:** 445/tcp — microsoft-ds / Samba SMB2/SMB3
- **CVE:** CVE-2016-2119 (CVSS **7.5**)
- **Description:** A flaw in `libcli/smb/smbXcli_base.c` within Samba allows man-in-the-middle attackers to bypass client-signing protection by abusing the `SMB2_SESSION_FLAG_IS_GUEST` or `SMB2_SESSION_FLAG_IS_NULL` flags. This enables attackers to spoof SMB2 and SMB3 server responses, potentially redirecting clients to rogue shares or capturing NetNTLM credentials.
- **Evidence:** Port 445 is open and accepting SMB connections. Without confirmed SMB signing enforcement or version confirmation, the risk of SMB2/SMB3 spoofing via null/guest session flags cannot be excluded. Tools such as Responder could exploit this in an adjacent network position.
- **Recommendation:** Upgrade to Samba 4.2.14+, 4.3.11+, or 4.4.5+. Disable guest and null session access at the OS and Samba configuration level (`map to guest = never`, `restrict anonymous = 2`). Deploy network IDS signatures for SMB null-session and guest-flag anomalies.
- **ATT&CK:** T1187 — *Forced Authentication* (Credential Access)

---

### [HIGH] Samba Privilege Check Bypass — Machine Account Creation

- **Service:** 445/tcp — Samba 4.x (SMB/Active Directory)
- **CVE:** CVE-2015-8467 (CVSS **7.5**)
- **Description:** The `samldb_check_user_account_control_acl` function in Samba fails to properly check for administrative privileges during machine account creation. In mixed-domain environments (Samba DC + Windows DC), remote authenticated users can bypass access restrictions and create unauthorised machine accounts, which can subsequently be used for persistence and lateral movement.
- **Evidence:** SMB port 445 is active. If the target is operating as a domain controller or member of a domain, this vulnerability is directly applicable. The absence of a version banner prevents definitive confirmation but does not eliminate the risk.
- **Recommendation:** Patch to Samba 4.1.22+, 4.2.7+, or 4.3.3+. Audit machine account creation privileges using Active Directory delegation reviews. Implement monitoring/alerting for unexpected machine account creation events (Windows Event ID 4741).
- **ATT&CK:** T1021.002 — *SMB/Windows Admin Shares* (Lateral Movement)

---

### [MEDIUM] SMB Network Share Enumeration — Information Disclosure Risk

- **Service:** 445/tcp — microsoft-ds (SMB)
- **CVE:** N/A (Configuration Issue)
- **Description:** An exposed SMB port without confirmed null-session restrictions allows unauthenticated or low-privileged attackers to enumerate available network shares, usernames, and domain/workgroup names using tools such as `smbclient`, `enum4linux`, or `CrackMapExec`. This information disclosure can directly enable targeted brute-force or credential-stuffing attacks.
- **Evidence:** Port 445 is openly reachable. No firewall ACL or VPN requirement was observed during scanning. The service did not return a version string, which may indicate default or misconfigured SMB deployment.
- **Recommendation:** Restrict SMB access to authorised hosts via host-based firewall rules (`ufw`, Windows Firewall, or iptables). Disable null sessions (`restrict anonymous = 2` on Windows; `restrict anonymous access = Yes` on Samba). Regularly audit exposed shares and remove any world-readable or writable shares.
- **ATT&CK:** T1135 — *Network Share Discovery* (Discovery)

---

### [MEDIUM] SMB Brute-Force Credential Attack Exposure

- **Service:** 445/tcp — microsoft-ds (SMB)
- **CVE:** N/A (Configuration / Exposure Issue)
- **Description:** The SMB service on port 445 is accessible without network-level access controls. This exposes authentication endpoints to automated brute-force and password-spray attacks targeting local or domain accounts. Weak or default credentials could allow full authenticated access to the system.
- **Evidence:** Port 445 is open with no evidence of account lockout policies, rate-limiting, or multi-factor authentication being enforced at the network layer.
- **Recommendation:** Enforce account lockout policies (e.g., lock after 5 failed attempts with a 30-minute reset window). Implement network-level controls (firewall/ACL) to restrict SMB access to known management hosts only. Consider deploying a SIEM/IDS to alert on repeated SMB authentication failures (Event ID 4625). Disable NTLM authentication where possible and enforce Kerberos.
- **ATT&CK:** T1110 — *Brute Force* (Credential Access)

## Remediation Priority

1. **[IMMEDIATE] Enforce SMB Signing & Apply MS16-075 / MS16-047 patches** — Eliminating CVE-2016-3225 and CVE-2016-2118 (BADLOCK) requires mandatory SMB signing (`RequireSecuritySignature`) and full patch application. These are the highest-risk findings and address the root cause of multiple vulnerabilities simultaneously.

2. **[URGENT] Upgrade Samba to latest stable release** — Address CVE-2016-2119 and CVE-2015-8467 by ensuring Samba is patched to at minimum 4.4.5+ (or current stable). Disable guest/null sessions in `smb.conf` immediately.

3. **[HIGH] Restrict SMB port 445 via host-based and network firewall** — SMB should never be exposed beyond the minimum required internal hosts. Apply `ufw`/`iptables`/Windows Firewall rules to whitelist only authorised source IPs. This single control mitigates the brute-force, share enumeration, and MitM risks significantly.

4. **[HIGH] Disable Null Sessions and Guest Access** — Set `restrict anonymous = 2` (Windows) or `map to guest = never` + `restrict anonymous access = Yes` (Samba) to prevent unauthenticated enumeration of shares, users, and domain information.

5. **[MEDIUM] Implement SMB Authentication Lockout & SIEM Alerting** — Configure account lockout policies and deploy monitoring for Event ID 4625 (failed logon) and 4741 (machine account creation) to detect brute-force and privilege abuse attempts in near-real-time.

6. **[LOW] Establish Authenticated Vulnerability Scanning & Asset Inventory** — Deploy an authenticated scanner to obtain exact OS/SMB versions for all assets, ensuring accurate, ongoing CVE tracking independent of service banners.
