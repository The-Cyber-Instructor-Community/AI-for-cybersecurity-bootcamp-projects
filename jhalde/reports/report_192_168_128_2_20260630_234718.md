### [CRITICAL] vsftpd 2.3.4 Backdoor — Unauthenticated Remote Code Execution

- **Service:** Port 21 / FTP / vsftpd 2.3.4
- **CVE:** CVE-2011-2523 (CVSS 10.0)
- **Description:** vsftpd version 2.3.4 was trojanised in a supply-chain compromise before its official release. The backdoor is triggered by sending a username containing the sequence `":)"` (smiley face), causing the daemon to open a root-level bind shell on **TCP port 6200**. No authentication is required. This results in complete, immediate, unauthenticated remote code execution as root.
- **Evidence:** nmap identified vsftpd 2.3.4 running on port 21. This specific version is universally confirmed in the security community as containing the backdoor payload. The service is openly reachable with no firewall restriction observed.
- **Recommendation:** Immediately shut down the vsftpd service. Replace with a modern, actively maintained FTP daemon (e.g., vsftpd ≥ 3.0.5) or eliminate FTP entirely in favour of SFTP over SSH. Verify the integrity of all installed binaries against known-good checksums. Conduct a full compromise assessment of the host.
- **ATT&CK:** T1210 — Exploitation of Remote Services

### [CRITICAL] Samba 3.0.20 — Unauthenticated Remote Code Execution via `username map script`

- **Service:** Port 445 / NetBIOS-SSN / Samba smbd 3.0.20-Debian
- **CVE:** CVE-2007-2447 (CVSS 10.0)
- **Description:** Samba versions 3.0.0 through 3.0.25rc3 contain a command injection vulnerability in the `username map script` configuration option. When this option is enabled, user-supplied input passed to `/bin/sh` is not sanitised, allowing a remote, unauthenticated attacker to execute arbitrary operating system commands with the privileges of the Samba daemon (typically root). This is a highly reliable, widely weaponised exploit requiring no valid credentials.
- **Evidence:** nmap confirmed Samba smbd 3.0.20-Debian on ports 139 and 445. This version falls squarely within the affected range. The `username map script` feature is enabled by default in the Metasploitable 2 configuration of this service.
- **Recommendation:** Upgrade Samba to the latest stable release (≥ 4.19.x). If upgrading is not immediately possible, remove or disable the `username map script` directive in `smb.conf` and restrict SMB access to trusted internal hosts only via firewall rules. Ports 139 and 445 should never be exposed to untrusted networks.
- **ATT&CK:** T1210 — Exploitation of Remote Services

### [CRITICAL] Telnet Service Exposed — Cleartext Credential Transmission

- **Service:** Port 23 / Telnet / Linux telnetd
- **CVE:** CWE-319 / No single CVE — Architectural insecurity (industry-accepted CRITICAL risk)
- **Description:** Telnet transmits all session data — including usernames, passwords, and command output — in plaintext over the network. Any attacker with the ability to intercept traffic on the same network segment (via ARP spoofing, a rogue switch port, or passive sniffing) can trivially capture administrative credentials. Telnet also lacks mutual authentication, making it susceptible to man-in-the-middle attacks. Telnet has been formally deprecated for over two decades.
- **Evidence:** nmap identified Linux telnetd listening on port 23. The service is accepting connections with no encryption layer observed.
- **Recommendation:** Disable and remove the telnet daemon immediately (`systemctl disable telnet`, remove `telnetd` package). Replace all Telnet-based remote access with **OpenSSH** (after upgrading it — see finding below). Block port 23 at the network perimeter firewall unconditionally.
- **ATT&CK:** T1040 — Network Sniffing

### [HIGH] OpenSSH 4.7p1 — Multiple Vulnerabilities Including Signal Handler Race Condition

- **Service:** Port 22 / SSH / OpenSSH 4.7p1 Debian 8ubuntu1 (protocol 2.0)
- **CVE:** CVE-2006-5051 (CVSS 8.1)
- **Description:** OpenSSH versions prior to 4.4 contain a signal handler race condition that can lead to a double-free memory corruption. If GSSAPI authentication is enabled, this may be leveraged by remote attackers to cause a denial of service or potentially achieve remote code execution. Additionally, OpenSSH 4.7p1 is approximately 18 years out of date and is likely affected by a large body of subsequently disclosed vulnerabilities (including CVE-2008-4109, CVE-2010-4755, and others) relating to memory corruption, information disclosure, and weak algorithm support.
- **Evidence:** nmap fingerprinted OpenSSH 4.7p1 on port 22. Current stable OpenSSH is 9.x; this version is dangerously end-of-life with no vendor support.
- **Recommendation:** Upgrade OpenSSH to the latest stable release immediately (≥ 9.7). Disable GSSAPI authentication if not required (`GSSAPIAuthentication no` in `sshd_config`). Enforce key-based authentication only, disable password authentication, and restrict SSH access via allowlisted source IPs. Disable weak ciphers and MAC algorithms.
- **ATT&CK:** T1210 — Exploitation of Remote Services

### [HIGH] ISC BIND 9.4.2 — Outdated DNS Server with Known Vulnerabilities

- **Service:** Port 53 / DNS / ISC BIND 9.4.2
- **CVE:** CVE-2016-1286 (CVSS 8.6)
- **Description:** ISC BIND 9.4.2 is a severely outdated DNS server (released circa 2007) with a long history of critical vulnerabilities. CVE-2016-1286 allows remote attackers to crash the named daemon via a crafted DNAME signature record, resulting in denial of service. Beyond this specific CVE, BIND 9.4.x is affected by numerous unpatched vulnerabilities including cache poisoning (CVE-2008-1447 — Kaminsky Attack), remote DoS, and DNS zone transfer exposure, allowing adversaries to enumerate the full internal DNS zone.
- **Evidence:** nmap identified ISC BIND 9.4.2 on TCP port 53. This version has been end-of-life for well over a decade. TCP/53 being open also suggests zone transfers may not be restricted.
- **Recommendation:** Upgrade BIND to the latest stable release (≥ 9.18.x LTS). Restrict recursive queries to authorised clients only. Disable zone transfers (`allow-transfer { none; };`) unless explicitly required, and limit them to known secondaries. Implement DNSSEC. Consider replacing BIND with a purpose-hardened resolver such as Unbound for recursive resolution.
- **ATT&CK:** T1590.002 — Reconnaissance: DNS

### [HIGH] Apache HTTP Server 2.2.8 with WebDAV — Outdated and Misconfigured Web Server

- **Service:** Port 80 / HTTP / Apache httpd 2.2.8 (Ubuntu) DAV/2
- **CVE:** CVE-2016-4979 (CVSS 7.5), multiple additional CVEs for Apache 2.2.x branch
- **Description:** Apache 2.2.8 is an end-of-life version (Apache 2.2 branch reached EOL in December 2017) with a substantial catalogue of known vulnerabilities. The presence of `DAV/2` in the server banner indicates **mod_dav (WebDAV) is enabled**, which can allow unauthenticated file upload and remote code execution if write permissions are misconfigured. Additionally, the verbose server banner discloses the exact server version and OS, aiding attacker reconnaissance. Apache 2.2.x is also affected by slowloris-style denial-of-service attacks and multiple mod_cgi vulnerabilities.
- **Evidence:** nmap returned the banner `Apache httpd 2.2.8 ((Ubuntu) DAV/2)` on port 80. The Nikto scan timed out, which may indicate a slow/overloaded service or anti-scanning behaviour, but the version banner alone is sufficient to confirm exposure. Gobuster returned no additional hidden paths, limiting the web attack surface assessment.
- **Recommendation:** Upgrade Apache to the current stable release (≥ 2.4.59). Disable WebDAV (`mod_dav`) unless it serves a specific, justified business purpose — and if retained, enforce authentication and restrict write-capable methods (PUT, DELETE). Suppress the server version banner (`ServerTokens Prod`, `ServerSignature Off`). Apply `mod_security` as a WAF layer. Restrict port 80 access where possible.
- **ATT&CK:** T1505.003 — Web Shell (persistence risk via WebDAV write access)

### [HIGH] R-Services Exposed (rexec / rlogin / rsh) — Unauthenticated Legacy Remote Access

- **Service:** Ports 512 (rexec), 513 (rlogin), 514 (rsh) / netkit-rsh rexecd / Netkit rshd
- **CVE:** CVE-1999-0651 / CWE-306 — Missing Authentication for Critical Function (industry-accepted HIGH risk)
- **Description:** The Berkeley r-services suite (rsh, rexec, rlogin) are critically insecure legacy protocols that pre-date modern security practices. They rely on IP-address-based trust via `.rhosts` and `/etc/hosts.equiv` files, transmit all data in plaintext, and are trivially bypassed via IP spoofing. If the target's `.rhosts` file contains permissive entries (common in Metasploitable configurations), an attacker can gain shell access without any password authentication whatsoever. These services have been deprecated since the 1990s.
- **Evidence:** nmap confirmed rexecd on port 512, rlogin on port 513, and Netkit rshd on port 514 — all openly accessible. All three services are active simultaneously.
- **Recommendation:** Immediately disable and remove all r-services (`rsh-server`, `rexec`, `rlogin` packages). Block ports 512, 513, and 514 at the perimeter firewall. Audit and delete all `.rhosts` and `hosts.equiv` files on the system. Replace any legitimate use case with SSH.
- **ATT&CK:** T1021.002 — Remote Services: SMB/Windows Admin Shares (analogous trust-based lateral movement via network services)

### [HIGH] Postfix SMTP — Open Mail Relay and Cleartext Authentication Risk

- **Service:** Port 25 / SMTP / Postfix smtpd
- **CVE:** CVE-2006-4434 (CVSS 7.5)
- **Description:** The Postfix smtpd service is exposed on port 25. While Postfix itself is generally well-maintained, the version on this end-of-life Ubuntu host is likely outdated. Port 25 exposed externally without TLS or authentication creates risk of open mail relay abuse (facilitating spam/phishing), SMTP user enumeration via `VRFY` and `EXPN` commands, and cleartext credential capture if SMTP AUTH is used without STARTTLS. CVE-2006-4434 in Sendmail/Postfix-adjacent configurations describes a use-after-free triggered by long header lines leading to daemon crashes.
- **Evidence:** nmap confirmed Postfix smtpd listening on port 25 with no indication of enforced TLS. The service is accessible without authentication for delivery attempts.
- **Recommendation:** Disable port 25 externally if this host does not serve as a legitimate mail server. If SMTP is required, enforce `STARTTLS` for all connections, disable `VRFY` and `EXPN` commands, configure strict relay restrictions (`mynetworks` to localhost only), and upgrade Postfix to the current stable release. Deploy SPF, DKIM, and DMARC records.
- **ATT&CK:** T1071 — Application Layer Protocol

### [MEDIUM] RPCBind / Portmapper Exposed — Service Enumeration and Attack Surface Expansion

- **Service:** Port 111 / RPC / rpcbind 2 (RPC #100000)
- **CVE:** CVE-2015-7236 (CVSS 7.5)
- **Description:** The rpcbind portmapper service is exposed on port 111, acting as a directory service for all RPC-based services on the host. This allows unauthenticated remote attackers to enumerate all registered RPC services and their port assignments, significantly expanding the attack surface map. CVE-2015-7236 describes a use-after-free in rpcbind 0.2.1 and earlier triggered by crafted PMAP_CALLIT packets that can crash the daemon. RPC services (particularly NFS and NIS) exposed via rpcbind have historically been vectors for privilege escalation and data exfiltration.
- **Evidence:** nmap confirmed rpcbind version 2 on port 111. The service is unauthenticated by design and openly accessible.
- **Recommendation:** Restrict access to port 111 via firewall rules to only trusted internal hosts that require RPC services. If NFS, NIS, or other RPC-dependent services are not required, disable rpcbind entirely. Upgrade rpcbind to the latest available version. Monitor RPC service registrations for unexpected entries.
- **ATT&CK:** T1135 — Network Share Discovery

## Remediation Priority

1. **[IMMEDIATE] Shut down or isolate the host entirely** — The combination of CVE-2011-2523 (vsftpd backdoor) and CVE-2007-2447 (Samba RCE) means any unauthenticated attacker on the same network can achieve root access within minutes. This host must not be reachable from any untrusted network segment.

2. **[IMMEDIATE] Remove vsftpd 2.3.4** — Uninstall the backdoored FTP daemon. Audit port 6200 for any existing reverse shell or bind shell connections indicating prior compromise.

3. **[IMMEDIATE] Patch or disable Samba 3.0.20** — Upgrade Samba or, at minimum, remove the `username map script` from `smb.conf` and block ports 139/445 at the firewall until a patched version is deployed.

4. **[URGENT] Disable all cleartext remote access protocols** — Remove Telnet (port 23), RSH (514), Rlogin (513), and Rexec (512) immediately. These provide trivial credential harvesting opportunities and, in the case of r-services, potentially unauthenticated shell access.

5. **[URGENT] Upgrade OpenSSH from 4.7p1 to current stable** — Replace the only encrypted remote access pathway with a secure, supported version. Enforce key-based authentication only.

6. **[HIGH] Upgrade Apache 2.2.8 and disable WebDAV** — Move to Apache 2.4.x LTS, disable `mod_dav`, suppress server banners, and audit the web root for any previously uploaded web shells.

7. **[HIGH] Upgrade ISC BIND 9.4.2 and harden DNS** — Replace the decade-old DNS server, restrict zone transfers, and enable DNSSEC to prevent cache poisoning and reconnaissance via DNS.

8. **[MEDIUM] Restrict SMTP relay and enforce TLS on Postfix** — Prevent open relay abuse, disable user enumeration commands, and enforce encrypted transport for all mail sessions.

9. **[MEDIUM] Firewall or disable RPCBind** — Restrict port 111 to trusted hosts to prevent unauthenticated service enumeration and reduce the attack surface for RPC-based vulnerabilities.
