CRITICAL vsftpd 2.3.4 Backdoor — Remote Code Execution

Service:** Port 21/tcp — vsftpd 2.3.4

CVE:** CVE-2011-2523 (CVSS 10.0)

Description: vsftpd version 2.3.4 was distributed with a deliberate backdoor introduced into its source code. When a username containing the string `:)` (smiley face) is submitted during login, the daemon opens a bind shell on TCP port 6200**, granting an unauthenticated remote attacker a root-level interactive shell with no credentials required. This is one of the most well-known supply-chain compromises in open-source history.

Evidence:** Nmap confirmed `vsftpd 2.3.4` running on port 21. This exact version string is the sole indicator needed to confirm the presence of the backdoor.

Recommendation:** Immediately disable and remove vsftpd 2.3.4. Replace with a patched, actively maintained FTP server (e.g., vsftpd 3.0.5+). If FTP functionality is not required, disable the service entirely and block port 21 at the firewall. Consider replacing FTP with SFTP (port 22) for secure file transfer.

ATT&CK:** T1210 — Exploitation of Remote Services

CRITICAL Samba 3.0.20 — Remote Code Execution via Username Map Script (CVE-2007-2447)

Service:** Port 445/tcp — Samba smbd 3.0.20-Debian

CVE:** CVE-2007-2447 (CVSS 9.3)

Description:** Samba versions 3.0.0 through 3.0.25rc3 are vulnerable to an unauthenticated remote command injection flaw in the `MS-RPC` `SamrChangePassword` function when the `username map script` configuration option is enabled. An attacker can inject arbitrary shell metacharacters into the username field, which are executed as the `root` user by the Samba daemon, resulting in full system compromise without any valid credentials.

Evidence:** enum4linux confirmed `Samba 3.0.20-Debian` on ports 139 and 445. The IPC share (`IPC$`) is accessible and the banner explicitly identifies the vulnerable version: *"metasploitable server (Samba 3.0.20-Debian)"*.

Recommendation:** Upgrade Samba immediately to a supported release (4.18+). Disable the `username map script` directive in `smb.conf` if present. Restrict SMB access (ports 139/445) to trusted internal hosts only using firewall rules. Consider disabling SMB entirely if file sharing is not required.

ATT&CK:** T1210 — Exploitation of Remote Services

HIGH R-Services Enabled — rexec / rlogin / rsh (Ports 512/513/514)

Service:** Ports 512/tcp (rexecd), 513/tcp (rlogind), 514/tcp (rshd) — Netkit R-Services

CVE:** CWE-287 — Improper Authentication / CVE class: inherently insecure-by-design protocols

Description: The legacy BSD R-Services (`rexec`, `rlogin`, `rsh`) provide remote command execution and login functionality with no encryption and host-based trust authentication** using `.rhosts` and `hosts.equiv` files. These services are considered inherently insecure: they transmit credentials in plaintext, rely on easily spoofed IP-based authentication, and are a well-known target for exploitation. If a `.rhosts` file contains `+ +`, any host can authenticate as any user without a password.

Evidence:** Nmap confirmed `netkit-rsh rexecd` on port 512, `rlogind` on port 513, and `Netkit rshd` on port 514 — all open and listening.

Recommendation:** Immediately disable all R-Services (`rexec`, `rlogin`, `rsh`). Remove or purge the `rsh-server` and `rlogin` packages. Block ports 512, 513, and 514 at the firewall. Replace with SSH for all remote access. Audit and remove any `.rhosts` or `hosts.equiv` files on the system.
